# Abduction and occupant dataset review

Reviewed: 2026-10-13. Scope: public primary-source descriptions, selected catalog entries, codebooks, access and reuse statements. Frontend baseline: `f52e0cd`. This is a source-selection review, not an import, a new incident census, or a finding that any reported event is independently verified.

## Finding

The new encounter feature uses a defensible structured starting layer from the five collections already preserved in this project. It is not justified to describe that layer as the best possible abduction dataset. No reviewed source establishes a complete, globally representative, independently verified abduction census, and no single source combines comprehensive event coverage, uniform investigation quality, precise dates/locations, detailed being descriptions, and confirmed permission for public redistribution.

The strongest next step for this map is targeted enrichment from the original CUFOS HUMCAT cards and Albert Rosales' author-hosted Humanoid Contact Database, followed by source reconciliation. These can recover descriptions and case references that sparse source codes omit. URECAT is especially useful for comparing conflicting versions. This ranking is our suitability judgment for this project, not a claim that these compilers' accounts are all reliable or uniquely original.

## What the current feature actually contains

The existing [encounter implementation report](ENCOUNTERS_20261013.md) records 702,893 catalog reports and a source-pinned index with 3,217 reported-abduction records: 2,984 from explicit source classifications and 233 from guarded own-report narratives. It separately retains 2,139 ambiguous category/mention records and 12,595 records describing beings. These are catalog-record counts, not deduplicated incidents or persons.

The feature extracted preserved UFOCAT classifications and narrative evidence across the current five-source corpus. It did not acquire the external collections below. Missing classification therefore means no indexed positive evidence under the current rules; it does not mean the source had no encounter or that all specialist archives were searched. The source-code meaning comes from the [CUFOS codebook](https://cufos.org/PDFs/UFOCAT%20Codebook%202023.pdf): Hynek CE4 supports an abduction category, while broader contact and mixed disappearance/teleportation codes need separate treatment.

## Concrete quality gaps and enrichment design

The present extraction layer lacks a systematic source-to-incident/person bridge; encounter-specific coverage comparisons; consistent recall-method fields; investigation chronology; primary-document page links; and attributed conflicting versions. More rows alone will not repair these gaps.

For a bounded first pilot, review 24 source entries across forced abduction, voluntary contact, entity without craft, partial date, repeated episode and hypnotically recovered narrative. Use HUMCAT originals and Rosales for coverage; use URECAT and linked original files to resolve disagreements. This is a proposed next phase, not work performed by this audit.

Each candidate should retain:

- Catalog/custodian, edition, native entry ID, URL and page/locator, source citation, and a hash where a permitted file is retained.
- Verbatim date/place fields, date precision, occurrence versus report/investigation date, coordinate evidence and uncertainty. A support-group mailing address or interview location is not an event location.
- Source-described being appearance, contact category, voluntary/involuntary/unknown status, reported craft relationship, recall method and hypnosis/investigation timing where explicit.
- Repeated-experience and person/episode distinction, privacy state, reuse state, attributed evaluation/alternative explanation, and conflicting-account notes.
- Existing canonical event IDs, join evidence, confidence and reviewer disposition. An unresolved candidate stays outside incident totals; a newly located version may enrich an existing record instead of creating another event.

Report pilot outcomes as **new evidence for existing reports**, **plausible new incident candidates**, **duplicates/shared sources**, **unresolved**, and **not eligible for import**. Keep map-report counts and distinct incident counts separate. Survey comparisons should expose their own respondent, item and phase denominators and remain separate from event heatmaps.

## Audit boundary and retention

Primary host/custodian pages and selected entries were reviewed online on 2026-10-13. Source-specific availability and terms can change. No private archive was accessed; no payment, terms-acceptance workflow, contact request, bulk crawl, corpus import or binary download was performed. Absence of a discovered public export is a bounded-search finding, not proof that a researcher has no data or would not share it under an agreement.

This document and the compact [source eligibility register](qa/abduction-dataset-review-20261013/sources.json) are the canonical outputs of this source-selection review; existing encounter data, raw records, coordinates, deployment and retained rollback are unchanged. Only these small text artifacts are added, with no new file above 100 MiB and no staging tree or full dataset copy. Retain them as unique research provenance; superseding them later should preserve this dated evidence boundary.
